# BUG-001: GET /v2/pokemons — при передаче букв в параметр in_pokeball возвращается сырая ошибка валидации вместо понятного сообщения

**Severity:** Minor  
**Priority:** Medium  
**Статус:** Open
**Примечание:** Через пользовательский интерфейс данный сценарий недостижим — фронт передаёт только валидные значения. Баг актуален для прямых обращений к API: интеграции, мобильные клиенты, скрипты.
## Описание

При передаче нечислового значения (строки) в query-параметр `in_pokeball` API возвращает сырую ошибку внутренней валидации pydantic вместо понятного пользовательского сообщения. При передаче числового значения, отличного от 0 или 1, API корректно возвращает читаемое сообщение об ошибке.

## Шаги воспроизведения

1. Отправить запрос `GET /v2/pokemons?in_pokeball=абракадабра` с заголовком `trainer_token`

## Ожидаемый результат

```json
{
    "status": "error",
    "message": "Значение in_pokeball невалидно (1 или 0)"
}
```

## Фактический результат

```json
{
    "status": "error",
    "message": "[{'type': 'int_parsing', 'loc': ('query', 'in_pokeball'), 'msg': 'Input should be a valid integer, unable to parse string as an integer', 'input': 'абракадабра'}]"
}
```

## Дополнительно

Поведение непоследовательно — два похожих невалидных значения возвращают разные форматы ошибок:

| Входные данные | Ответ |
|----------------|-------|
| `in_pokeball=абракадабра` (строка) | Сырая ошибка pydantic |
| `in_pokeball=5` (число не 0/1) | Читаемое сообщение `"Значение in_pokeball невалидно (1 или 0)"` |

Сырое сообщение раскрывает внутреннюю реализацию (pydantic, названия полей, структуру валидации).

## Окружение

- API: https://api.pokemonbattle.ru
- Метод: GET /v2/pokemons
- Параметр: `in_pokeball=абракадабра`
