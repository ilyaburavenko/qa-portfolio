# BUG-002: GET /v2/pokemons — при передаче букв в параметр status возвращается сырая ошибка валидации вместо понятного сообщения

**Severity:** Minor  
**Priority:** Medium  
**Статус:** Open

## Описание

При передаче нечислового значения (строки) в query-параметр `status` API возвращает сырую ошибку внутренней валидации pydantic вместо понятного сообщения. Аналогичная проблема воспроизводится и для параметра `in_pokeball` (BUG-001).

Через пользовательский интерфейс данный сценарий недостижим — фронт передаёт только валидные значения. Баг актуален для прямых обращений к API: интеграции, мобильные клиенты, скрипты.

## Шаги воспроизведения

1. Отправить запрос GET /v2/pokemons?status=абракадабра с заголовком trainer_token

## Ожидаемый результат

```json
{
    "status": "error",
    "message": "Значение status невалидно"
}
```

## Фактический результат

```json
{
    "status": "error",
    "message": "[{'type': 'int_parsing', 'loc': ('query', 'status'), 'msg': 'Input should be a valid integer, unable to parse string as an integer', 'input': 'абракадабра'}]"
}
```

## Дополнительно

Параметр `sort` при аналогичном невалидном вводе возвращает корректное сообщение "Значение sort невалидно" — поведение непоследовательно между параметрами одного эндпоинта.

| Параметр | Невалидное строковое значение | Ответ |
|----------|-------------------------------|-------|
| sort | абракадабра | Читаемое: "Значение sort невалидно" |
| status | абракадабра | Сырая ошибка pydantic |
| in_pokeball | абракадабра | Сырая ошибка pydantic (BUG-001) |

## Окружение

- API: https://api.pokemonbattle.ru
- Метод: GET /v2/pokemons
- Параметр: status=абракадабра
