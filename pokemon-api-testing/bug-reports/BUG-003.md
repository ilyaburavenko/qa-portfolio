# BUG-003 — Сырая ошибка pydantic при отсутствии поля password_new в PUT /v2/trainers/edit_password

**Статус:** Open  
**Severity:** Minor
**Затрагивает:** прямые обращения к API (не UI)
**Примечание:** через интерфейс недостижимо, актуально 
для интеграций и прямых клиентов API
**Эндпоинт:** `PUT /v2/trainers/edit_password`

---

## Описание

При отсутствии обязательного поля `password_new` в теле запроса API возвращает сырую техническую ошибку pydantic вместо читаемого сообщения. При этом если поле передаётся с пустым значением — API возвращает корректное читаемое сообщение об ошибке. Поведение непоследовательно.

---

## Шаги воспроизведения

1. PUT /v2/trainers/edit_password
2. Header: trainer_token
3. Body: {"password_old": "123453456Il"} — поле password_new отсутствует

---

## Ожидаемый результат

```json
{
    "status": "error",
    "message": "Поле password_new обязательно для заполнения"
}
```

---

## Фактический результат

```json
{
    "status": "error",
    "message": "[{'type': 'json_invalid', 'loc': ('body', 40), 'msg': 'JSON decode error', 'input': {}, 'ctx': {'error': 'Expecting property name enclosed in double quotes'}}]"
}
```

---

## Примечание

Для сравнения: передача пустой строки {"password_old": "123453456Il", "password_new": ""} возвращает корректное читаемое сообщение с кодом 400. Аналогичный паттерн сырых ошибок pydantic зафиксирован в BUG-001 и BUG-002.

---

## Окружение

- Host: https://api.pokemonbattle.ru
- Версия API: v2
- Инструмент: Postman / pytest + requests
